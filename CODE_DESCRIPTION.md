Этот документ дополняет `README.md` и `dino.py`. Он предназначен для того, чтобы
можно было подробно объяснить устройство проекта, не заглядывая в каждый файл.

## 2. Общая архитектура

Проект состоит из четырёх слоёв:

```
┌──────────────────────────────────────────────────────────────┐
│ 1. Браузер (Playwright)                                      │
│    open_browser(), INIT_SCRIPT, BRIDGE_SCRIPT                │
│    - подмена index.js локальным файлом                       │
│    - управление временем через performance.now()             │
│    - пошаговый вызов window.__dino.step(action)              │
└───────────────────────┬──────────────────────────────────────┘
                        │ snapshot / action
┌───────────────────────▼──────────────────────────────────────┐
│ 2. Окружение                                                 │
│    DinoEnv, encode_state(), compute_reward()                 │
│    - кадр -> 49 признаков, стек 3 кадров -> 147              │
│    - награда за дистанцию и правильную позу                  │
└───────────────────────┬──────────────────────────────────────┘
                        │ (s, a, r, s')
┌───────────────────────▼──────────────────────────────────────┐
│ 3. Обучение                                                  │
│    DQN, ReplayBuffer, expert_action(), train()               │
│    - imitation learning от эвристики                         │
│    - DQN: replay, target network, Huber, Adam                │
└───────────────────────┬──────────────────────────────────────┘
                        │ dqn_model.npz
┌───────────────────────▼──────────────────────────────────────┐
│ 4. Воспроизведение                                            │
│    play_forever()                                             │
│    - жадный выбор argmax Q                                    │
│    - 60 кадров/с, бесконечный цикл до Ctrl+C                  │
└──────────────────────────────────────────────────────────────┘
```

Ключевая идея: игра остаётся оригинальной, а агент не «вмешивается» в её правила.
Он только:

1. получает из движка снимок состояния;
2. выбирает одно из трёх действий;
3. передаёт действие обратно в движок.

## 3. Браузерный слой

### 3.1. `open_browser(headless)`

Последовательность:

1. Проверяется наличие локального `index.js`.
2. Запускается Playwright:
   ```python
   pw = sync_playwright().start()
   ```
3. Аргументы запуска:
   - всегда `--mute-audio`;
   - для headless добавляется `--disable-gpu`;
   - для видимого окна добавляются `--start-maximized` и `--window-size=1366,768`.
4. Сначала пробуется `channel="chrome"`, если не получается — bundled Chromium.
   Это важно для Windows и Linux: на Linux Chrome может быть не установлен.
5. Создаётся страница:
   - headless: `viewport={"width": 1280, "height": 800}`;
   - видимый режим: `no_viewport=True`, размер окна задаёт сама ОС.
6. Внедряется `INIT_SCRIPT`.
7. Читается локальный `index.js` и регистрируется подмена:
   ```python
   page.route("**/index.js", route_handler)
   ```
   То есть браузер загружает HTML/CSS/картинки с сайта, но исполняемый код игры
   берётся из локального файла.
8. Открывается `GAME_URL`.
9. Ждём появления `window.Runner.instance_`.
10. Выполняется `BRIDGE_SCRIPT`, который подключает управление.
11. Возвращаются `pw`, `browser`, `page`.

### 3.2. `INIT_SCRIPT` — псевдо-часы

Оригинальная игра использует `performance.now()` и собственный
`requestAnimationFrame`. Для обучения нужно, чтобы один шаг агента = один кадр
игры с фиксированным `deltaTime = 1000/60 мс`.

Поэтому переопределяется `performance.now()`:

```js
value: function () {
  return window.__dinoNow === null ? originalNow() : window.__dinoNow;
}
```

Пока мост не активирован, работает настоящее время. После активации
`window.__dinoNow` увеличивается ровно на `FRAME = 1000 / 60` за каждый вызов
`step()`. Благодаря этому физика детерминирована и не зависит от скорости
машины.

### 3.3. `BRIDGE_SCRIPT` — JavaScript-мост

Мост решает пять задач.

#### 3.3.1. Остановка собственного цикла игры

```js
if (r.raqId) {
  cancelAnimationFrame(r.raqId);
  r.raqId = 0;
}
r.updatePending = false;
r.scheduleNextUpdate = function () { this.updatePending = false; };
```

После этого игра обновляется **только** по вызову из Python.

#### 3.3.2. Включение arcade-режима

В оригинале режим включается после нажатия `Space` в функции `playIntro()`.
Мост заменяет её на мгновенный вариант:

```js
r.playIntro = function () {
  this.playingIntro = false;
  this.tRex.playingIntro = false;
  this.playing = true;
  this.activated = true;
  this.containerEl.style.webkitAnimation = '';
  this.containerEl.style.width = this.dimensions.WIDTH + 'px';
  this.containerEl.style.height = this.dimensions.HEIGHT + 'px';
  var box = document.getElementById('messageBox');
  if (box) box.style.visibility = 'hidden';
  document.body.classList.add(R.classes.ARCADE_MODE);
  this.setArcadeModeContainerScale();
};
r.playIntro();
```

Это убирает маленькое поле шириной 44 px и делает картинку такой же, как на
сайте после нажатия пробела. Настройки игры при этом не меняются.

#### 3.3.3. Защита от остановки при изменении размера окна

Оригинальный `adjustDimensions()` при `playing=true` вызывает `stop()`.
Из-за этого при разворачивании окна динозавр замирал. Мост оборачивает метод:

```js
const adjustDimensionsOriginal = r.adjustDimensions.bind(r);
r.adjustDimensions = function () {
  adjustDimensionsOriginal();
  if (!this.crashed) {
    this.playing = true;
    this.paused = false;
    this.raqId = 0;
    this.updatePending = false;
  }
  this.setArcadeModeContainerScale();
};
```

После пересчёта размеров игра снова находится в состоянии «идёт».

#### 3.3.4. `snapshot()` — сбор признаков

Тип препятствия кодируется числом:

| `type` | kind |
|---|---|
| `CACTUS_SMALL` | 1 |
| `CACTUS_LARGE` | 2 |
| `PTERODACTYL` | 3 |

Для каждого препятствия считается:

```js
const front = t.xPos + dinoWidth;
const dx = o.xPos - front;                       // расстояние до динозавра
const speed = Math.max(2, r.currentSpeed + (o.speedOffset || 0));
const dt = dx / speed;                           // время до встречи
```

Важно, что в движке столкновение проверяется только с `obstacles[0]`, пока тот
полностью не уйдёт за левую границу. Поэтому вводится отдельное понятие
**блокер** — первое препятствие, у которого правый край ещё впереди левого края
динозавра:

```js
const blockerRaw = raw.find(function (o) {
  return o.xPos + o.width > t.xPos + 2;
}) || raw[0];
```

Именно блокер является «текущей целью» для эвристики и сети.

`snapshot()` возвращает:

- `dead` — `r.crashed`;
- `dist`, `score` — дистанция и счёт;
- `speed` — текущая скорость;
- `dino` — высота над землёй, вертикальная скорость, флаги `jumping`/`ducking`/`speedDrop`, координаты;
- `obstacles` — три ближайших препятствия (недостающие заполнены пустыми);
- `blocker` — текущая цель;
- `engine` — дубль списка препятствий для отладки.

#### 3.3.5. `step(action)` — один кадр

```js
if (t.ducking && action !== 2) t.setDuck(false);

if (action === 1) {
  if (!t.jumping) {
    t.startJump(r.currentSpeed);
    t.endJump();
  }
} else if (action === 2) {
  if (t.jumping) {
    t.setSpeedDrop();      // ускоренное падение — штатная механика игры
  } else if (!t.ducking) {
    t.setDuck(true);       // приседание на земле
  }
}

window.__dinoNow += FRAME;
r.update();
return snapshot();
```

Действия полностью совпадают с кнопками оригинальной игры:

- `0` — ничего;
- `1` — прыжок (аналог `Space`/`ArrowUp`);
- `2` — `ArrowDown`: на земле приседание, в воздухе быстрое падение.

## 4. Пространство состояний

### 4.1. Один кадр — 49 признаков

`encode_state(snap)` возвращает вектор из 49 чисел `float32`.

#### Группа A — состояние динозавра (5 чисел)

| Признак | Нормализация |
|---|---|
| `heightAbove` | `/60`, обрезка `[-0.2, 1.5]` |
| `vy` | `/12`, обрезка `[-1.2, 1.0]` |
| `jumping` | `0/1` |
| `ducking` | `0/1` |
| `speed` | `/13`, обрезка `[0, 1.2]` |

#### Группа B — препятствия (4 × 9 = 36 чисел)

Берутся три «сырых» препятствия и текущий блокер. Для каждого:

| Признак | Описание |
|---|---|
| `kind == 1` | one-hot кактуса маленького |
| `kind == 2` | one-hot кактуса большого |
| `kind == 3` | one-hot птеродактиля |
| `dx / 300` | расстояние до динозавра, обрезка `[-1, 2]`; если препятствия нет — `2` |
| `dt / 60` | время до встречи, обрезка `[0, 2]`; если нет — `2` |
| `width / 60` | ширина |
| `y / 150` | координата верхнего края |
| `height / 50` | высота |
| `speedOffset` | скорость птеродактиля, обрезка `[-1, 1]` |

#### Группа C — явные признаки эвристики (8 чисел)

Они дублируют пороги эксперта, но в числовой форме:

| Признак | Условие |
|---|---|
| `need_duck` | `kind == 3 and y <= 80` |
| `jumpable` | есть препятствие и не нужно приседать |
| `vy > 0` | динозавр поднимается |
| `dx < 105` | цель близко |
| `dx > 180` | цель уже позади/следующая |
| `jump_window` | `45 < dx < 95` |
| `jump_window and not jumping` | можно начать прыжок |
| `any obstacle` | есть ли блокер |

Эти признаки оказались критичными: без них сеть ошибалась на границах
порогов (например, прыгала на 1 кадр раньше).

### 4.2. Стек кадров

`DinoEnv.frames` — `deque(maxlen=3)`. В `reset()` все три элемента заполняются
одинаковым кадром, дальше каждый `step()` добавляет новый и выбрасывает самый
старый.

Итоговая размерность:

```
3 кадра × 49 признаков = 147 чисел
```

Стек нужен, чтобы сеть видела не только положение, но и динамику: направление
прыжка, ускорение падения, сближение с препятствием.

## 5. Функция награды

`compute_reward(prev, cur, action)`:

1. Если `cur["dead"]` — возвращается `-15.0`.
2. Базовая награда:
   ```python
   0.01 + max(0.0, cur["dist"] - prev["dist"]) / 100.0
   ```
3. Небольшой штраф за действие:
   - действие `0` — `0`;
   - действие `1` — `0.008`;
   - действие `2` — `0.004`.
4. Формирующие бонусы, если блокер на расстоянии `0 < dx < 150`:

   - для высокого птеродактиля (`y <= 80`) правильная поза — `ducking`;
   - для кактуса/низкого птеродактиля правильная поза — `jumping` и высота
     не ниже `needed_height = 136 - y + 6`;
   - если поза правильная — `+0.06`;
   - если выбрано правильное действие — `+0.04`;
   - если `dx < 95` и поза неправильная — `-0.08`;
   - если `dx < 100` и неправильная поза (приседание перед кактусом или прыжок под
     высоким птеродактилем) — ещё `-0.06`.

Формирующие бонусы ускоряют обучение, но в режиме `play` они не участвуют —
там выбирается только `argmax Q`.

## 6. Эвристика-учитель

`expert_action(snap)` — детерминированная политика, на которой обучалась сеть.

Правила:

1. Нет препятствия → `0`.
2. Высокий птеродактиль (`kind == 3`, `y <= 80`):
   - если динозавр в прыжке, поднимается и `dx > 180` → `2` (быстрее приземлиться
     к следующему препятствию);
   - иначе `2`, если `dx < 105`, в противном случае `0`.
3. Кактус или низкий птеродактиль:
   - если динозавр уже прыгает:
     - при `vy > 0` и `dx > 180` → `2`;
     - иначе `0`;
   - если не прыгает и `45 < dx < 95` → `1`;
   - иначе `0`.

Параметр `rng` оставлен в сигнатуре для совместимости, но шум намеренно не
добавляется: случайные действия портили метки для клонирования.

## 7. Нейросеть DQN

### 7.1. Архитектура

```
147 -> 256 -> 256 -> 3
```

- вход: стек из 3 кадров;
- два скрытых слоя по 256 нейронов с ReLU;
- выход: три Q-значения для действий `0`, `1`, `2`.

Реализация на чистом `numpy`, потому что в окружении нет `torch`/`tensorflow`.
Обратное распространение написано вручную.

### 7.2. Инициализация

Веса каждого слоя инициализируются по He:

```python
rng.normal(0.0, math.sqrt(2.0 / fan_in), (fan_in, fan_out))
```

Смещения инициализируются нулями.

### 7.3. Прямой проход

`_forward(x, params)`:

- для первых двух слоёв: `h = max(0, W @ h + b)`;
- для последнего: `h = W @ h + b` без ReLU — это Q-значения.

Возвращаются сами Q и кэш `(h, z)` для backprop.

### 7.4. Оптимизатор

`_adam_step(grads)`:

1. Считается глобальная норма всех градиентов.
2. Если норма больше `5`, все градиенты масштабируются:
   ```python
   scale = 5.0 / norm
   ```
3. Дополнительно каждый градиент обрезается в диапазон `[-5, 5]`.
4. Применяется Adam:
   - `beta1 = 0.9`;
   - `beta2 = 0.999`;
   - `eps = 1e-8`;
   - `lr = 5e-4` (после фазы эксперта уменьшается до `1.25e-4`).

### 7.5. Режим 1 — клонирование эксперта

`imitate_batch(states, actions)`:

1. Считаются Q-значения.
2. По ним строится softmax:
   ```python
   probs = softmax(q)
   ```
3. Минимизируется кросс-энтропия с меткой эксперта:
   ```python
   probs[range(n), actions] -= 1.0
   dq = probs / n_actions
   ```
4. Через `dq` считаются градиенты всех слоёв и делается шаг Adam.

По сути, сеть учится предсказывать действие эвристики, а не просто копировать
его в таблицу.

### 7.6. Режим 2 — DQN

`train_batch(states, actions, rewards, next_states, terminals)`:

1. Online-сеть считает Q для текущих состояний.
2. Target-сеть считает Q для следующих состояний.
3. Цель Беллмана:
   ```python
   target = r + GAMMA * max(Q_target(s')) * (1 - terminal)
   ```
   где `GAMMA = 0.99`.
4. Ошибка `diff = q - target` сжимается через Huber:
   ```python
   dq = clip(diff, -1, 1) / batch_size
   ```
5. Шаг backprop + Adam.

Target-сеть обновляется раз в `TARGET_SYNC_EVERY = 1000` шагов через
`sync_target()`. Это делает цели обучения стабильнее.

### 7.6.1. Важный факт про текущую модель

В текущих настройках:

```python
TRAIN_STEPS = 120_000
EXPERT_STEPS = 120_000
```

То есть весь стандартный прогон `train --steps 120000 --fresh` находится в
фазе клонирования эксперта. Чистый DQN-дообучатель включится, только если
уменьшить `EXPERT_STEPS` или увеличить число шагов обучения. Это сделано
намеренно: чистый DQN с нуля давал больше столкновений в тестах.

### 7.7. Сохранение и загрузка

`save()` пишет сжатый `.npz`:

- `state_dim`;
- `online_W0`, `online_b0`, ...;
- `target_W0`, `target_b0`, ...;
- `train_step`.

`load()` создаёт `DQN(state_dim)` и подставляет веса. Если файл битый или
старой архитектуры — возвращает `None`, и вызывающий код создаёт новую сеть.

## 8. Replay-буфер

`ReplayBuffer` — кольцевой массив фиксированной ёмкости `60_000`:

```python
states       # float32, [capacity, 147]
actions      # int64,   [capacity]
rewards      # float32, [capacity]
next_states  # float32, [capacity, 147]
terminals    # float32, [capacity]
```

- `add()` записывает переход по указателю `pos` и сдвигает указатель по кругу.
- `sample(batch_size)` берёт `64` случайных индексов **без повторов**.

Зачем это нужно: соседние кадры игры сильно коррелированы. Случайная выборка
разрушает эту корреляцию и делает обновления более независимыми.

## 9. Окружение `DinoEnv`

Обертка над JS-мостом в стиле Gym:

- `reset()`:
  1. вызывает `window.__dino.reset()`;
  2. получает снимок;
  3. кодирует его в 49 признаков;
  4. заполняет стек из трёх кадров;
  5. возвращает состояние и снимок.

- `step(action)`:
  1. вызывает `window.__dino.step(action)`;
  2. считает награду через `compute_reward(prev, cur, action)`;
  3. обновляет `prev`;
  4. добавляет новый кадр в стек;
  5. возвращает `(state, reward, dead, snapshot)`.

`terminal=True` выставляется **только** при реальном столкновении. Ограничение
эпизода в `MAX_EPISODE_STEPS = 4000` — это техническая обрезка, поэтому она не
помечается как terminal и не обрывает бутстрепинг в формуле Беллмана.

## 10. Обучение `train()`

Константы:

| Константа | Значение | Назначение |
|---|---|---|
| `TRAIN_STEPS` | 120 000 | число шагов обучения |
| `EXPERT_STEPS` | 120 000 | длина фазы клонирования |
| `MIN_REPLAY` | 2 000 | минимальный размер буфера перед обновлением |
| `REPLAY_CAPACITY` | 60 000 | ёмкость буфера |
| `BATCH_SIZE` | 64 | размер мини-батча |
| `GAMMA` | 0.99 | коэффициент обесценивания награды |
| `LEARNING_RATE` | 5e-4 | скорость обучения |
| `TARGET_SYNC_EVERY` | 1 000 | частота обновления target-сети |
| `EPSILON_START/END/DECAY` | 1.0 / 0.02 / 25 000 | затухание исследования |
| `SAVE_EVERY` | 10 000 | частота сохранения модели |
| `SEED` | 42 | воспроизводимость |
| `MAX_EPISODE_STEPS` | 4 000 | техническая длина отрезка |

Цикл обучения:

1. Считается `epsilon` по экспоненте.
2. На шаге `EXPERT_STEPS + 1` скорость обучения уменьшается в 4 раза и
   синхронизируется target-сеть.
3. Если `step <= EXPERT_STEPS`:
   - действие из `expert_action()`;
   - обновление через `imitate_batch()`.
4. Иначе:
   - действие через `agent.act()` (epsilon-greedy);
   - обновление через `train_batch()`.
5. Каждые `TARGET_SYNC_EVERY` шагов — `sync_target()`.
6. Каждые `SAVE_EVERY` шагов — `save()`.
7. При столкновении или достижении `MAX_EPISODE_STEPS` — `reset()`.

## 11. Бесконечная игра `play_forever()`

1. Загружается `dqn_model.npz`. Если размерность не 147 — выводится сообщение
   и запуск прекращается.
2. `state, snap = env.reset()`.
3. Вычисляется интервал кадра:
   ```python
   frame_interval = (1000 / 60) / speed if speed > 0 else 0
   ```
4. В цикле:
   - действие = `argmax(Q(state))`;
   - если в `snap["obstacles"]` нет ни одного препятствия (первые 3 секунды
     по `CLEAR_TIME`), принудительно берётся действие `0`;
   - выполняется `env.step(action)`;
   - выдерживается ровно 60 кадров/с с учётом времени самого шага:
     ```python
     next_tick += frame_interval
     delay = next_tick - time.perf_counter()
     if delay > 0:
         time.sleep(delay)
     ```
   - при столкновении увеличивается счётчик жизней и вызывается `reset()`;
   - раз в 6000 кадров печатается статистика.
5. `Ctrl+C` завершает цикл.

Ограничения по времени или очкам нет — игра продолжается до остановки
пользователем.

## 12. Кроссплатформенность

### Windows

- `play.bat`, `train.bat`, `auto.bat`;
- `python` из PATH;
- консоль может показывать кракозябры из-за кодировки — на logical работы не влияет.

### Linux/macOS

- `setup.sh` ставит зависимости и Chromium:
  ```bash
  python3 -m pip install -r requirements.txt
  python3 -m playwright install chromium
  ```
- `play.sh`, `train.sh`, `auto.sh` используют `python3` и `exec`.
- `.gitattributes` гарантирует `LF` в `.sh`, иначе возможна ошибка
  `bad interpreter: /bin/bash^M`.
- Если системных библиотек не хватает:
  ```bash
  sudo python3 -m playwright install-deps chromium
  ```

### Headless-режим

`can_show_window()`:

- `DINO_HEADLESS=1` → всегда headless;
- Linux без `DISPLAY`/`WAYLAND_DISPLAY` → headless (например, SSH);
- Windows/macOS → видимое окно.

В `main()` режим `auto` сначала обучается headless, затем переоткрывает браузер
с видимым окном, если это возможно.

## 14. Почему динозавр кажется «медленно падающим»

Физика полностью берётся из `index.js`:

- обычная гравитация: `GRAVITY = 0.6`;
- ускоренное падение: `setSpeedDrop()` и `SPEED_DROP_COEFFICIENT = 3`.

Замер политики за 20 000 кадров:

```
actions {0: 10724, 1: 314, 2: 8962}
jump-starts: 314
air-action2: 7942
```

То есть сеть очень часто использует действие `2` именно в воздухе — падение
ускоренное. Моменты более долгого «зависания» соответствуют действию `0` и
обычной гравитации. Настройки игры не изменялись.

Если нужно визуально быстрее:

```bat
python dino.py play --speed 5
```

## 15. Типичные вопросы для защиты

**Почему не используются PyTorch/TensorFlow?**  
Их нет в окружении. DQN на `numpy` реализован вручную: прямой проход, backprop,
Adam, target-сеть и replay. Это демонстрирует понимание алгоритма, а не только
умение вызвать готовую библиотеку.

**Почему не меняли `index.js`?**  
Это было требование: исходный код игры должен остаться неизменным. Управление
реализовано через JavaScript-мост, который подключается к уже созданному
`Runner.instance_`.

**Почему сначала эвристика, а не сразу DQN?**  
Чистый DQN с нуля в тестах давал десятки столкновений за 100 000 кадров.
Клонирование надёжной эвристики дало политику с 0 столкновений.

**Почему 3 кадра, а не один?**  
Один кадр не показывает направление движения. Стек из трёх кадров даёт сети
информацию о скорости и траектории прыжка.

**Почему в `play` нет случайности?**  
Воспроизведение должно быть детерминированным: выбирается `argmax Q`. Epsilon
используется только во время обучения.

**Что значит «бесконечно»?**  
В коде нет лимита по времени или очкам. Практическая проверка — 100 000 кадров
без столкновений (около 28 минут при 60 FPS). Математической гарантии от
любой случайной последовательности препятствий дать нельзя, но протестированная
политика демонстрирует устойчивую игру.

**Почему игра не останавливается при разворачивании окна?**  
Мост оборачивает `adjustDimensions()` и возвращает `playing=true` после того,
как оригинальный движок вызвал `stop()`.
