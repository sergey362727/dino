# Процесс обучения DQN-агента

Этот файл подробно описывает, как именно обучается `dqn_model.npz`: откуда
берутся данные, что происходит на каждом шаге, как устроены две фазы обучения,
как читать логи и как запустить обучение заново.

Общая архитектура проекта описана в `CODE_DESCRIPTION.md`, а краткие команды —
в `README.md`.

---

## 1. Что обучается

Обучается нейросеть, которая по состоянию игры предсказывает три Q-значения —
ожидаемую будущую награду для действий:

| Действие | Смысл |
|---|---|
| `0` | ничего не делать |
| `1` | прыжок |
| `2` | приседание на земле / ускоренное падение в воздухе |

Архитектура сети:

```
147 -> 256 -> 256 -> 3
```

- 147 входных чисел = стек из 3 кадров по 49 признаков;
- два скрытых слоя по 256 нейронов с ReLU;
- выход — три Q-значения без активации.

Воспроизведение использует только `argmax Q`. Обучение может использовать
 исследовательская стратегия `epsilon-greedy`, но в текущей конфигурации фактически
 работает фаза клонирования эксперта (подробнее в разделе 5).

## 3. Откуда берутся обучающие данные

Игра запускается через Playwright, но её собственный цикл
`requestAnimationFrame` отключён. Вместо этого Python вызывает:

```python
next_state, reward, terminal, snap = env.step(action)
```

Что внутри:

1. `DinoEnv.step(action)` вызывает JavaScript:
   ```js
   window.__dino.step(action)
   ```
2. JS-мост:
   - применяет действие к оригинальному `Runner.instance_.tRex`;
   - увеличивает псевдо-часы ровно на `1000/60 мс`;
   - вызывает оригинальный `r.update()`;
   - возвращает `snapshot()`.
3. Python:
   - считает награду `compute_reward(prev, cur, action)`;
   - кодирует новый кадр в 49 признаков;
   - добавляет кадр в стек из трёх последних кадров;
   - возвращает состояние из 147 чисел.

Псевдо-часы нужны для детерминированности: один шаг обучения всегда равен
одному кадру при 60 FPS, независимо от скорости компьютера.

## 4. Что попадает в буфер опыта

Каждый шаг в `ReplayBuffer` сохраняется кортеж:

```python
(state, action, reward, next_state, terminal)
```

Где:

- `state` — состояние из 147 чисел до действия;
- `action` — выбранное действие `0/1/2`;
- `reward` — награда за кадр;
- `next_state` — состояние после действия;
- `terminal` — `1`, только если произошло столкновение.

Буфер имеет вид кольца:

```text
[0][1][2] ... [59997][59998][59999]
                         ^
                         pos
```

Когда `pos` доходит до конца, он возвращается в начало и перезаписывает
самые старые записи.

## 5. Две фазы обучения

В `train()` есть две фазы, переключаемые константой `EXPERT_STEPS`.

### Фаза 1 — клонирование эксперта

```python
if step <= EXPERT_STEPS:
    action = expert_action(env.prev, rng)
```

Действия берутся не из сети, а из детерминированной эвристики
`expert_action()`. Сеть при этом учится предсказывать эти действия через
`imitate_batch()`.

Зачем так сделано:

- чистый DQN с нуля в тестах давал десятки столкновений за 100 000 кадров;
- клонирование надёжной эвристики дало политику с 0 столкновений;
- эвристика основана на точной геометрии игры, поэтому метки почти не содержат
  шума.

### Фаза 2 — обычный DQN

```python
else:
    action = agent.act(state, epsilon, rng)
```

Сеть сама выбирает действие по `epsilon-greedy`, а обновление идёт через
`train_batch()` — классический Q-learning с target-сетью.

### Важный факт про текущую конфигурацию

Сейчас в `dino.py`:

```python
TRAIN_STEPS = 120_000
EXPERT_STEPS = 120_000
```

То есть при стандартной команде:

```bat
python dino.py train --steps 120000 --fresh
```

вся процедура проходит в фазе клонирования. Вторая фаза **не наступает**.
Это осознанный выбор: лучший результат показала именно политика, обученная
на метках эксперта.

Если хотите включить DQN-дообучение, есть два способа:

1. Увеличить число шагов:
   ```bat
   python dino.py train --steps 200000 --fresh
   ```
   Тогда шаги 120001–200000 пройдут в фазе DQN.

2. Уменьшить `EXPERT_STEPS` в `dino.py`, например до `40000`.

Предупреждение: при `EXPERT_STEPS=40000` в ранних тестах было 12 столкновений
за 100 000 кадров, тогда как при 120 000 — 0. Поэтому стандартная конфигурация
использует полное клонирование.

## 6. Константы обучения

| Константа | Значение | Назначение |
|---|---|---|
| `TRAIN_STEPS` | 120 000 | число шагов по умолчанию |
| `EXPERT_STEPS` | 120 000 | граница между фазой эксперта и DQN |
| `MIN_REPLAY` | 2 000 | минимальный размер буфера перед первым обновлением |
| `REPLAY_CAPACITY` | 60 000 | ёмкость буфера |
| `BATCH_SIZE` | 64 | размер мини-батча |
| `GAMMA` | 0.99 | коэффициент обесценивания будущих наград |
| `LEARNING_RATE` | 5e-4 | скорость обучения |
| `TARGET_SYNC_EVERY` | 1 000 | как часто копировать веса в target-сеть |
| `EPSILON_START` | 1.0 | начальная вероятность случайного действия |
| `EPSILON_END` | 0.02 | минимальная вероятность случайного действия |
| `EPSILON_DECAY` | 25 000 | скорость затухания epsilon |
| `SAVE_EVERY` | 10 000 | как часто сохранять модель |
| `SEED` | 42 | воспроизводимость |
| `MAX_EPISODE_STEPS` | 4 000 | техническая длина отрезка жизни |

## 7. Пошаговый разбор цикла `train()`

### Шаг 1. Фиксация случайности

```python
random.seed(SEED)
np.random.seed(SEED)
rng = np.random.default_rng(SEED)
```

Инициализация Python, numpy и отдельного генератора `rng` одинакова при каждом
запуске. Это нужно, чтобы результаты были воспроизводимыми.

### Шаг 2. Определение размерности состояния

```python
first = page.evaluate("() => window.__dino.reset()")
state_dim = len(encode_state(first)) * FRAME_STACK
```

`encode_state()` возвращает 49 чисел, `FRAME_STACK = 3`, значит
`state_dim = 147`.

### Шаг 3. Загрузка или создание модели

```python
agent = DQN.load() if load_existing else None
if agent is None or agent.sizes[0] != state_dim:
    agent = DQN(state_dim)
agent.sync_target()
```

- Если запуск с `--fresh`, существующая модель игнорируется.
- Если размерность загруженной модели не 147, она заменяется новой.
- Перед обучением online- и target-сети синхронизируются.

### Шаг 4. Создание буфера и окружения

```python
buffer = ReplayBuffer(REPLAY_CAPACITY, state_dim)
env = DinoEnv(page)
state, _ = env.reset()
```

### Шаг 5. Вычисление epsilon

```python
epsilon = EPSILON_END + (EPSILON_START - EPSILON_END) * math.exp(-step / EPSILON_DECAY)
```

На первом шаге `epsilon ≈ 0.96`, к шагу 100 000 он падает почти до `0.02`.

### Шаг 6. Переход в фазу DQN

```python
if step == EXPERT_STEPS + 1:
    agent.lr = LEARNING_RATE / 4.0
    agent.sync_target()
```

Если фаза DQN наступает, скорость обучения уменьшается в 4 раза, чтобы не
разрушить уже выученную политику. Target-сеть синхронизируется с online-сетью.

### Шаг 7. Выбор действия

```python
if step <= EXPERT_STEPS:
    action = expert_action(env.prev, rng)
else:
    action = agent.act(state, epsilon, rng)
```

В первой фазе действие детерминированное, во второй — epsilon-greedy.

### Шаг 8. Шаг игры

```python
next_state, reward, terminal, snap = env.step(action)
buffer.add(state, action, reward, next_state, terminal)
state = next_state
best_score = max(best_score, snap["score"])
```

Переход попадает в буфер, состояние сдвигается, статистика обновляется.

### Шаг 9. Обновление сети

```python
if buffer.size >= MIN_REPLAY:
    batch = buffer.sample(BATCH_SIZE)
    if step <= EXPERT_STEPS:
        losses.append(agent.imitate_batch(batch[0], batch[1]))
    else:
        losses.append(agent.train_batch(*batch))
```

Пока в буфере меньше 2000 переходов, обучение не производится — буфер
наполняется.

### Шаг 10. Синхронизация, сохранение, логи

```python
if step % TARGET_SYNC_EVERY == 0:
    agent.sync_target()

if step % SAVE_EVERY == 0:
    agent.save()
```

Каждые 1000 шагов обновляется target-сеть, каждые 10 000 шагов модель
сохраняется в `dqn_model.npz`.

### Шаг 11. Лог каждые 1000 шагов

```python
avg_loss = float(np.mean(losses[-1000:])) if losses else 0.0
phase = "эксперт" if step <= EXPERT_STEPS else "DQN"
```

В консоль выводятся:

- номер шага;
- фаза;
- текущий epsilon;
- средняя ошибка за последние 1000 обновлений;
- номер эпизода;
- лучший счёт;
- размер буфера;
- прошедшее время.

### Шаг 12. Reset

```python
if terminal or ep_steps >= MAX_EPISODE_STEPS:
    state, _ = env.reset()
    ep_steps = 0
    episode += 1
```

Важно: `terminal=True` только при столкновении. Достижение 4000 кадров — это
техническая обрезка эпизода. Она не помечается как terminal, поэтому формула
Беллмана продолжает бутстрепироваться через `next_state`.

## 8. Как устроено клонирование эксперта

`imitate_batch()` решает задачу многоклассовой классификации по Q-значениям.

### Прямой проход

```python
q, caches = self._forward(states, self.params)
```

### Softmax по Q

```python
q = q - q.max(axis=1, keepdims=True)
exp_q = np.exp(q)
probs = exp_q / np.sum(exp_q, axis=1, keepdims=True)
```

Вычитание максимума нужно для численной устойчивости.

### Градиент кросс-энтропии

```python
probs[np.arange(len(actions)), actions] -= 1.0
dq = probs / len(actions)
```

Для правильного действия градиент равен `(p - 1) / N`, для остальных — `p / N`.
Это стандартная производная softmax + cross-entropy.

### Обратное распространение

Для каждого слоя:

```python
grads[f"W{i}"] = h.T @ dout
grads[f"b{i}"] = dout.sum(axis=0)
dh = dout @ self.params[f"W{i}"].T
dout = dh * (caches[i - 1][1] > 0)
```

`(z > 0)` — маска ReLU: градиент проходит только через положительные
активации.

### Шаг оптимизатора

```python
self._adam_step(grads)
```

## 9. Как устроен DQN-шаг

`train_batch()` используется только во второй фазе.

### Цель Беллмана

```python
target = r + GAMMA * max(Q_target(s')) * (1 - terminal)
```

Если `terminal == 1`, будущая награда обнуляется.

### Huber loss

```python
diff = q - targets
dq = np.clip(diff, -1.0, 1.0) / len(actions)
```

Клип на `[-1, 1]` делает обновление устойчивее к случайным большим наградам.

### Зачем target-сеть

Если использовать одну и ту же сеть и для предсказания, и для цели, цель
постоянно «двигается» вместе с весами — обучение может расшататься. Поэтому:

- online-сеть обновляется каждый батч;
- target-сеть — раз в 1000 шагов через `sync_target()`.

## 10. Оптимизатор Adam

`_adam_step()` делает три вещи:

### 10.1. Глобальная отсечка градиента

```python
norm = math.sqrt(sum(float(np.sum(g * g)) for g in grads.values()))
scale = 1.0 if norm <= 5.0 else 5.0 / max(norm, 1e-9)
```

Если суммарная норма больше 5, все градиенты уменьшаются.

### 10.2. Дополнительная клиппинг по значению

```python
g = np.clip(g * scale, -5.0, 5.0)
```

### 10.3. Обновление Adam

```python
m = beta1 * m + (1 - beta1) * g
v = beta2 * v + (1 - beta2) * g * g
mhat = m / (1 - beta1 ** t)
vhat = v / (1 - beta2 ** t)
param += -lr * mhat / (sqrt(vhat) + eps)
```

Параметры: `beta1=0.9`, `beta2=0.999`, `eps=1e-8`.

## 11. Сохранение модели

`agent.save()` пишет `dqn_model.npz` в сжатом виде:

```python
{
  "state_dim": 147,
  "online_W0": ..., "online_b0": ...,
  "online_W1": ..., "online_b1": ...,
  "online_W2": ..., "online_b2": ...,
  "target_W0": ..., "target_b0": ...,
  ...
  "train_step": 120000
}
```

Сохраняются обе сети — online и target. При загрузке `DQN.load()` создаёт
объект `DQN(state_dim)` и подставляет веса. Если архитектура не совпадает,
загрузка считается неудачной и создаётся новая модель.

## 12. Как читать логи обучения

Пример строки:

```text
step= 10000 | эксперт | eps=0.677 | loss=0.0001 | эпизод=2 | лучший счёт=31999 | память= 10000 | 17.0s
```

Расшифровка:

| Поле | Что означает |
|---|---|
| `step=10000` | обработан 10 000-й кадр |
| `эксперт` | идёт фаза клонирования |
| `eps=0.677` | текущая вероятность случайного действия (понадобится в фазе DQN) |
| `loss=0.0001` | средняя ошибка за последние 1000 обновлений |
| `эпизод=2` | сколько раз был reset |
| `лучший счёт=31999` | максимум за время обучения |
| `память=10000` | сколько переходов уже в буфере |
| `17.0s` | прошедшее время |

В фазе эксперта `loss` обычно очень маленький — это нормально: эвристика
детерминированная и легко предсказывается.

## 15. Воспроизводимость

Обучение детерминировано в следующих пределах:

- сид `SEED = 42` фиксирует Python, numpy и `rng`;
- время в игре фиксировано (`performance.now()` подменён);
- действия эксперта детерминированы;
- мини-батчи выбираются через `rng` с фиксированным начальным значением.

Небольшая недетерминированность возможна из-за:

- порядка событий браузера;
- округлений в JavaScript при генерации препятствий;
- версии Chromium.

Поэтому точные веса могут слегка отличаться между машинами, но качество
политики сохраняется.

## 16. Частые проблемы

### Модель не загружается

Сообщение:

```text
Не удалось загрузить модель (...); начнём с нуля.
```

Причины: битый файл, другая размерность, другая архитектура. Решение —
переобучить с `--fresh`.

### Буфер долго не заполняется

До `MIN_REPLAY = 2000` обновлений нет. Это нормально: первые 2000 кадров идут
только на сбор переходов.

### В логах всегда «эксперт»

Это нормально при `EXPERT_STEPS = TRAIN_STEPS`. Фаза DQN не включена в
стандартной конфигурации.

### Обучение шло, но игра стала хуже

Скорее всего, включилась фаза DQN или было использовано слишком мало шагов
клонирования. Вернитесь к `120000 --fresh`.

---

## 17. Связь обучения с режимом `play`

`play_forever()` не обучается. Он:

1. загружает `dqn_model.npz`;
2. проверяет, что размерность равна 147;
3. на каждом кадре берёт `argmax Q`;
4. держит 60 кадров/с;
5. продолжает бесконечно до `Ctrl+C`.

То есть всё, что «знает» агент, записано в весах модели. Эвристика
`expert_action()` в `play` не вызывается.

## 18. Краткое резюме

Обучение представляет собой имитационное клонирование надёчной эвристики с
последующей (по умолчанию не используемой) возможностью DQN-дообучения. Игра
служит окружением, пошаговый мост даёт детерминированный кадр, буфер накапливает
переходы, сеть предсказывает действия через softmax по Q-значениям, а оптимизатор
Adam с отсечкой градиента обновляет веса. Итоговая модель сохраняется в
`dqn_model.npz` и используется жадной политикой в бесконечной игре.
